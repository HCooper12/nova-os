# Every door, one Nova (1 Oct 2026)

His words, verbatim: "Holding the nova core should allow me to capture anything
through nova no matter how I speak with it… Nova needs to perform exactly like
Siri, Claude, ChatGPT etc. Where it doesn't matter the way that I speak with it
and where I speak with it but you can perform every single function and action
that is capable within the platform no matter how it is done. So if I would open
the nova core and speak with it directly or if I was in the middle for verbal
conversation or if I was typing into it I should be able to do anything I want
within it such as adding links and telling it to add it to my recipe vault,
asking it to research and capture something, ask it to analyse the video which
would then be delegated to the watcher agent etc."

This audit was written first, against `main` at 8da5106 ("before"). It was then
checked again against branch `build-everydoor` ("after"). Before-lines cite
8da5106 and after-lines cite the branch. Every claim below was read in the code.
None of it was run against a real model or his real vault.

**The one path, after:** every door ends at the ask lane. The strict grammar
(`verbs.js:1172 parseCommand` → `verbJobs.js parseJobCommand`) handles a
sentence it is sure of, with no model. Anything else goes to the model's
`ACT {"verb",…}` line. Its catalogue is generated by `describeForModel()`
(`verbs.js:1023`, printed into the prompt at `claudeCode.js:326`). The Coach,
Leader, Researcher and Librarian are reached by the existing consult rail
(`consultCapability('nova')`, `claudeCode.js:303`). Both paths run the same
`runVerb` (`verbs.js:1044`). It does the same validation and the same
model-choice gate (`verbs.js:1060`), and lands the same Inbox receipt with an
undo.

## The hold

Before: `SummaryDock.jsx:82` `onLongPress={v.openCaptureSheet || v.holdNovaText}`
raised the capture composer. `novaThread.enterFocus` existed but nothing called
it (`valsNovaThread.js`, "his call pending").

After: `onLongPress={v.holdNovaCore || v.holdNovaText}` (`SummaryDock.jsx:86`;
`valsChrome.js:524`, `summary` only). `App.holdNovaCore` (`App.jsx:6870`)
leaves a pending hold and goes to the Nova tab. When the thread registers its
focus (`valsNovaThread.js:165`) it takes the hold (`consumeNovaHold`,
`App.jsx:6881`): the core comes up full screen and the microphone opens through
the thread's own talk. The CaptureSheet still opens from the Inbox's hint line
(`InboxSummary.jsx:454`) and still renders from the dock. Other styles keep
`holdNovaText`.

## Not verified

- **No real model.** The model's ACT path was tested with a stub `claude` that
  emits the directive; whether the real model picks the right verb from the
  generated catalogue has not been observed.
- **No real lane ran.** Every job lane (Watcher, weave, Researcher, recipe
  import, briefing, Librarian, study, browser, practice) was injected. The
  recipe-page reader was tested on a fixture page, not a live recipe site.
- **No device.** The hold, the mic opening from it, and the presence running
  `doOrb` were not observed on his iPhone. A long-press is not a user gesture
  on iOS: the core will come up, but the microphone may need a tap if iOS
  refuses to start it from a hold.
- **No real Shortcut** has sent `files` to `/ask/sync`.
