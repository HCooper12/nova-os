## Home — `mission` (both idioms)

**Purpose:** the one screen he opens every day — the day's living status (body, calendar, plan) plus whatever needs his voice or his yes/no right now, drawn from one view model so nothing on it can be a fiction.

**Idioms.** `MissionControl` (`src/screens/MissionControl.jsx:88-91`) checks `v.structured` (set from `st.novaStyle === 'cupertino'` in `src/vals/valsChrome.js:526`) and, if true, returns `<MissionStructured v={v}/>` instead of drawing its own "Command Core" HUD — one `valsMission()` view model (`src/vals/valsMission.js:120`) feeds both. Command idiom, top to bottom (`MissionControl.jsx`): moments (prMoment/runningPlan/landedMoment) → hero (eyebrow row + greeting/tagline + hero cluster) → BODY strip (4 rings + 4 metric tiles) → 3-up row (Suggested Focus / Today / Concept Revisit) → Nova Is Working → (The One Thing / Today's Top 3 + Stuck + Command Deck) → Nova Noticed → 2-up vault shortcut cards → (mobile only) Agents strip. Cupertino idiom (`MissionStructured.jsx`) renders the SAME sections as grouped-list `Group`/`GRow` cards (`src/AppleLayout.jsx:21,46`) in one of three **hour-dependent ORDERS** (`src/screens/MissionStructured.jsx:42-47`, asserted complete in dev by `assertOrdersCover` `:49-60`):
  - **morning** (`hour<10`): working, hero, **vitals**, wrap, plan, stuck, lead, practice, focus, today, deck, review, noticed, shortcuts, agents — the body report leads.
  - **day** (`10≤hour<17`): working, wrap, focus, lead, practice, plan, stuck, today, deck, hero, **vitals**, noticed, review, shortcuts, agents — what-to-do-next leads; vitals step back.
  - **evening** (`hour≥17`): working, wrap, focus, plan, stuck, lead, practice, today, deck, vitals, review, hero, noticed, shortcuts, agents — Wrap the day IS the news, leading under anything still running.
  `leadFirst` (`valsMission.js:932`) can additionally promote `lead` to the front of whichever order is active inside the hour before a work block (`promoteLead`, imported from `src/workBlock.js`, applied at `MissionStructured.jsx:562-565`). Sections not present (no `wrapCard`, no `stuckCard`, etc.) are simply absent — never a placeholder.

### Command-idiom differences (what the classic HUD shows that cupertino doesn't, and vice versa)

- Command keeps a large **hero cluster**: the living Nova core plus three orbiting conic-progress satellites (sleep/steps/protein, `Sat`/`Cluster`, `src/screens/MissionControl.jsx:37-82`) with two decorative spinning dashed orbit rings behind it (`orbStyle`, `:31-35`). Cupertino replaces this with a flat 84–104px core + text (`:194-226`) — no orbiting satellites, no decorative orbit rings.
- Command's headline is a large serif-gradient tagline beneath an oversized bold greeting (`:320-322`); cupertino's is a plain `h1` + a smaller gradient serif line (`:592-593`) — visually much quieter.
- Command's vitals/BODY strip is one flat panel (rings row + 4-metric grid, always visible, `:358-382`); cupertino's `Vitals` is a foldable `Group` with a promoted focal tile (`:228-256`) that can collapse to a one-line instrument.
- Command's shortcuts render as a 2-up bordered card grid with hover glow (`:647-658`); cupertino renders them as plain `GRow`s inside one `Group` (`:531-544`).
- Command shows Suggested Focus / Today / Concept Revisit as three side-by-side panels in a fixed row (`rowA`, `:384-477`); cupertino stacks them as separate foldable `Group`s that can land anywhere in the hour's order (they are not adjacent).
- **Cupertino-only:** the fold/instrument system (F23) has no command equivalent — command always shows every present section in full, unfolded, in a fixed structural order (moments → hero → BODY → 3-up row → working → one-thing/plan/stuck/deck → noticed → shortcuts → agents) rather than the hour-dependent `ORDERS`.
- **Command-only:** the `heroGrid`/`cardsGrid`/`rowA` two-column CSS grid layouts that only make sense with acreage (`src/screens/MissionControl.jsx:93-97`) — cupertino is a single `760px`-max column (`:575`).

### Haptics vocabulary (`haptics.js`) — the words and where the chrome uses them

Five words only (`PATTERNS`, `src/haptics.js:12-25`): **tick** (a state flip — set ticked, tab hop), **commit** (something filed), **threshold** (a gesture passed its commit bar), **celebrate** (a personal record), **warn** (a refusal/failed write — three sharp pulses). Delivery path is chosen live per device (`nativeHaptics()` Capacitor shell → Vibration API → iOS-web transparent-switch overlay → nothing, `:39-95`).
- Chrome usages: `MobileChrome.jsx` dock tabs and top-bar chips fire `tick` on every `Interactive onClick` (`:32,60,69,75,77,80,118,129`). `TextAction`/`Chip`/`Button` in `Controls.jsx` default their `haptic` prop to `'tick'` (`Controls.jsx:90,121,186`). `Pill` in `AppleLayout.jsx` also defaults to `'tick'` (`:93,96`). `swipeAction.js` fires `threshold` on both a swipe-row commit (`:118`) and an option-pager page (`:196`). `MissionStructured.jsx`'s fold toggle fires `tick` on every open/close (`:178`). `useLongPress` (`longPress.js:25`) fires a raw `navigator.vibrate(10)` directly rather than going through the word vocabulary — the one bypass in the surveyed files.
