# Nova OS — the native shell

**Why this exists.** iOS gives a web app no vibration API, so every native app
ticks on a toggle and the Nova PWA could not. His approval, 6 Sep 2026: wrap
the same web app in a native shell so taps reach the Taptic Engine. Nothing
else changes — the shell **loads the live URL**
(`https://hcooper12.github.io/nova-os/`, see `capacitor.config.json` →
`server.url`), so every GitHub Pages deploy reaches the native app on its
next open, with no App Store release in between. The PWA on the Home Screen
keeps working beside it.

**How haptics reach the web app.** The shell injects `window.Capacitor` into
the page; `src/haptics.js` looks for it live and routes the five patterns
(tick / commit / threshold / celebrate / warn) to the Haptics plugin
(impact / notification / selectionChanged). In a plain browser the same calls
fall back to `navigator.vibrate`, which iOS Safari ignores — so the web build
needs no native import and never breaks outside the shell.

## What was done from the Mac (no Xcode needed)

- `capacitor.config.json` at the repo root — app id `com.haydencooper.novaos`,
  live `server.url`, dark status bar, Nova's void colour behind the web view.
- `@capacitor/core`, `@capacitor/ios`, `@capacitor/haptics`,
  `@capacitor/status-bar` (runtime 8.x) and `@capacitor/cli` in package.json.
- `ios/` — the Xcode project, generated by `npx cap add ios` (Swift Package
  Manager, no CocoaPods).
- `src/haptics.js` — the bridge described above.

## What only you can do (this Mac has the Command Line Tools, not Xcode)

1. **Install Xcode** from the Mac App Store (~12 GB), open it once so it
   installs its components, then point the tools at it:
   `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`.
2. In the repo: `npm run native:ios` — this runs `npx cap sync ios` (copies
   the config + plugins into the project) and opens `ios/App/App.xcodeproj`.
3. In Xcode: select the **App** target → **Signing & Capabilities** → tick
   *Automatically manage signing* → **Team**: your Apple ID (a free "Personal
   Team" works). If Xcode complains the bundle id is taken, change it to
   anything unique (e.g. `com.haydencooper.novaos2`) — it is only an
   identifier.
4. Plug in the iPhone, unlock it, pick it as the run destination, press **Run**
   (⌘R). First time: on the phone, *Settings → General → VPN & Device
   Management* → trust your developer certificate.
5. Open Nova, tap a Deck/List switch or fold a Mission Control section — you
   should feel it.

**The free-team caveat.** An app signed with a free Personal Team expires
after **7 days** and must be re-run from Xcode. A paid Apple Developer
membership (US$99/year) gives year-long signing and, if ever wanted, TestFlight
and the App Store. That is a separate decision; nothing here needs it.

**Updating later.** `npm run native:ios` again whenever `capacitor.config.json`
or the plugin list changes. Web changes need nothing — the shell loads the
live site.

## Live Activities: Nova on the lock screen and in the real Dynamic Island

His ask, 12 Oct 2026. Two cards, both drawn by the `NovaLiveActivityExtension`
target (`ios/App/NovaLiveActivity/`) from data the web app sends through the
`NovaLiveActivity` plugin (`ios/App/App/NovaLiveActivityPlugin.swift`,
registered in `NovaBridgeViewController.swift`):

- **Workout**: while a session is live. A ring of sets done of total in the
  next lift's muscle hue, the routine, "Next: <lift>", the session clock, and
  the rest countdown with a draining bar. iOS ticks the clocks itself, so the
  rest timer stays right with the phone locked and Nova asleep.
- **Job**: long work he started (a book read, an ingest, research): what is
  running and for how long, then "Ready" when it lands.

The data is built in `src/liveActivityModel.js` and sent from
`src/IslandFeed.jsx`; `NovaActivityAttributes.swift` must match it field for
field (`server/test/liveActivityModel.test.js` checks that).

### Your steps (after the shell steps above work)

1. Xcode → the **NovaLiveActivityExtension** target → Signing & Capabilities →
   the same Team as the App target. Its id is
   `com.haydencooper.novaos.LiveActivity`; if you changed the app's id, keep
   this one as `<app id>.LiveActivity`.
2. Run on the iPhone (⌘R). On the phone: Settings → Nova OS → Live Activities
   must be on (it is by default).
3. Start a workout in Nova, tick a set, lock the phone: the card is on the
   lock screen and the island, with the rest counting down.

### Limits, honestly

- **Updates only arrive while Nova is open.** A card's clocks keep ticking on
  their own, but a set ticked elsewhere or a job that finishes while the phone
  is locked will not change it until Nova next opens. Updating a card from
  the Mac needs Apple push (APNs), which needs the paid developer account.
- A tap on the card opens Nova where you left it, not a particular screen.
- Nothing here has been compiled yet (no Xcode on this Mac). The Swift was
  parse-checked only; the first build may need small fixes.

## Honest limits

- Haptics only work inside this shell; the Home Screen PWA stays silent.
- The shell is a WKWebView, so Safari-only quirks (audio priming, the 16px
  input rule) still apply. The connection to the Mac still goes over Tailscale
  from the web origin — nothing about that changed.
- Nothing here was built or run on a device yet: this Mac has no Xcode. The
  project is scaffolded and committed; the first build is yours.
